# LXI 1.6.2 remaining requirements — 2026-11-07

**This is the earlier same-day audit.** Several gaps were implemented and verified later in the session. For the final state and remaining work, read the [end-of-day summary](PROGRESS_2026-11-07.md) and [maintained requirements matrix](LXI.md). The audit below retains the observations and follow-up links as historical evidence.

This is an engineering gap review against the [Device Specification 1.6.2](https://public.lxistandard.org/specifications/LXI_1.6_Specifications/LXI_Device_Specification_1.6.2_2026-04-02.pdf) and the identification-related portions of [LXI API 1.1](https://public.lxistandard.org/specifications/LXI_1.6_Specifications_Archive/LXI_API_Extended_Function_1.1_2024-05-10.pdf), the minimum API revision listed by Device Specification 1.6.2. It is not an exhaustive certification checklist, a conformance declaration, or a claim that every unlisted rule passes. Existing historical reports retain the state at their test date.

## Live checks completed without configuration changes

Used the running Pi application and a separate Windows PC. The production certificate was explicitly trusted by the test client; hostname verification remained enabled. The private key and production Web password were not copied or used.

- Confirmed production listeners on 443, 8443 and SCPI 5025. Public `/`, `/lxi`, `/network`, `/help`, `/lan-status` and `/lxi/identification` returned 200 over both HTTPS ports with HTTP/1.1.
- Forced TLS 1.2 and TLS 1.3 separately; both certificate-verified HTTPS requests succeeded. Rejection of all obsolete TLS versions/cipher combinations was not independently tested.
- Fetched the advertised XSD from the Pi and validated its gateway and connected-radio XML. Gateway identity fields matched the TCP `*IDN?` reply. No radio setting or transmission command was issued.
- An unauthenticated `/api/status` returned 401. Password changes and authorized setting writes were covered by previous tests, not repeated in this audit.
- Received all four production DNS-SD services. HTTP/LXI/HTTPS pointed to `civi.local.` port 443; raw SCPI pointed to 5025. Identity TXT fields were present.
- The local panel reported normal. The user has separately confirmed Identify, LAN Fault and recovery on the attached screen, and successful production browser access on 443.
- Ethernet was operating at **100 Mb/s full duplex**, with runtime auto-negotiation on. The NIC advertised 10/100/1000 capabilities. The stored profile reported auto-negotiate `no`; the runtime/profile relationship and default provisioning should be reconciled before claiming the whole rule passes. No link settings were changed.
- IPv4 Ping to the wired address succeeded. `icmp_echo_ignore_all` was 0. A hostname Ping used IPv6, so it is not counted as another IPv4 test.

## Known implementation gaps

Follow-up implementation: blank-field factory restoration, the standard identification schema URL and LXI XML error responses were subsequently implemented and tested. See [current behavior and verification](LXI_DEFAULTS_API.md). The corresponding rows below preserve the gaps observed at audit time; they are no longer a claim that those implementations are absent. The running production process needs a manual restart to load them.

| Priority | Requirement | Evidence / remaining work |
|---|---|---|
| 1 | Device 9.5.7, 9.5.8: blank/whitespace hostname and Description restore factory defaults | Current hostname/description validation rejects blank values. Define immutable device defaults separately from user/acquired names, resolve blanks to those defaults, persist and test the Web and helper paths. Do not confuse this operation with LCI, which restores the last user-configured names. |
| 1 | Device 10.2; API 23.10.6.3, 23.10.7: identification schema endpoints | `/InstrumentIdentification/2.0` works, but live GET `/lxi/schemas/InstrumentIdentification/2.0` returned 404. Serve the identification schema at both the required location and the compatibility location. Review required identification response headers; current response is `application/xml`, while API 1.1's identification table specifies `text/xml` and the Device specification notes header omission may occur in compliant implementations. |
| 1 | Device 10.2; API 23.10.4.4: LXI error XML | A harmless unsupported POST to `/lxi/identification` returned the appropriate 405 status but `text/plain`, not `LXIProblemDetails` XML. Add schema-valid error responses to the standardized LXI identification endpoints without changing CIVI's unrelated JSON API contract. Review the remaining applicable common-method rules and ready/pending semantics. |
| 2 | Device 10.5.2, 9.5.6: disable mDNS and DNS-SD | The switch withdraws CIVI groups but leaves Avahi hostname responses and other OS advertisements active. Define device-wide behavior with a bounded privileged operation, persistent state and LCI recovery; test using IP access while names are unavailable. |
| 2 | Device 2.4.5, 8.13: local recovery when wired LAN is disconnected | Helper snapshot requires an active wired profile. The LAN RESET mechanism must also work when unplugged/disconnected; select the configured profile unambiguously without relying on an active connection. Test from the attached console and restore the user's configuration. |
| 3 | Device 6.1, 6.2, 11.1, 11.2: IVI driver, documentation and registration | No IVI Generation 2026/2014 driver is provided. PyVISA examples and a raw SOCKET server do not replace it. Implement and validate a conforming driver and VISA address handling, provide its documentation, and register it with the IVI Foundation. Registration is an external deliverable even if interconnection/certification testing is deferred. |

The runtime app deliberately omits an LXI version claim and logos. Functional declarations (1.4.5/1.4.6, 9.2), identification version semantics, and labeling/logo requirements (2.6, 9.9) remain release/conformance work. Do not add a logo or change the declaration merely to make a checklist appear complete.

## Implementation exists, but evidence is incomplete

Further follow-up: Avahi-based device-wide mDNS disabling and LCI re-enable are now implemented. Actual stop/activation blocking and fresh-query disappearance/recovery were verified on the Pi. The corresponding historical gap above is superseded by [current switch behavior and remaining acceptance checks](RPI_MDNS.md).

| Area | Rules | Required verification |
|---|---|---|
| DHCP and AutoIP | 8.6, 8.6.1, 8.6.3, 8.6.5–8.6.7, 8.6.10 | Controlled server/packet capture: requested subnet/gateway/DNS options, successful lease, changed options on renewal, expiry stops use of the expired address, DHCP absence/return and AutoIP behavior. Prior AutoIP success does not prove these rules. The 30-second DHCP suggestion in 8.6.2 is a recommendation, not a mandatory pass criterion. |
| Duplicate addresses | 7.3, 8.7, 8.10 | NM profile `ipv4.dad-timeout=-1`; the installed NM manual describes a global override or 200 ms fallback, and no override was found in the inspected configuration files. This is evidence of an OS detection path, not proof. Inject duplicate static/DHCP/link-local addresses in an isolated network, verify conflicting addresses are not used and the appropriate fault is shown. An extra CIVI detector is not inherently required if the OS satisfies the rule. |
| Link change and names | 7.3, 10.3.1.1, 10.7, 10.8 | Real two-host hostname collision, duplicate acquired hostname, reboot reuse/restoration, Avahi restart, reconnection and address changes. Service-instance collisions were tested; that does not establish hostname conflict behavior. |
| Network settings retention | 9.5 | Gateway/DNS application and readback, persistence after reboot, and successful rollback with those fields. Static address and hostname changes already have practical evidence. Review whether prefix-length entry sufficiently presents the required subnet-mask information. |
| Ping control | 8.2–8.4; 9.5.3 recommended Web control | Replies/default-on are confirmed. Linux provides a disable method, but CIVI does not expose or document a complete user control flow. Document and verify that method and LCI re-enable; Web control is recommended, not itself a mandatory rule. |
| Naming clients | 10.3.3/10.3.4, 10.6 | DHCP option 12 must not overwrite the user-selected mDNS name; inspect actual DHCP behavior. Verify outgoing `.local.` resolution and reverse lookups for link-local addresses on the Pi, not only Windows resolving the Pi. Dynamic-DNS-specific rules are conditional on supporting that capability. |
| Physical/default configuration | 2.4.5, 2.5.2.1, 7.1–7.7 | Keep the local display/keyboard as part of the defined device, verify usable local recovery independent of network state, runtime/default auto-negotiation and network-interface scope. Actual 100 Mb/s operation is confirmed. Determine Auto-MDIX capability or provide the required notice if unsupported. |
| Web/API robustness | 9.1, 9.8, 9.14, 10.2 | Additional browsers, normal/initializing/disconnected radio states, malformed/unsupported LXI requests, all required headers and schemas, consistent readiness and absence of custom APIs in reserved paths. Passing an XSD alone is insufficient. |

MAC labeling correction: Device 7.2 permits a user-accessible display **or** an affixed label. The existing local MAC display is valid evidence for this requirement; a physical MAC sticker is not an additional mandatory software gap. A masked publication photo is fine, but the actual device must show its real MAC.

## Scope and next order

Further follow-up: IPv4 Ping now has authenticated Web read/save controls with verified runtime and persistent sysctl settings. Actual new API/helper tests suppressed and restored replies on both wired and WLAN interfaces while production HTTPS/SCPI remained accessible. The earlier Ping-control gap above is historical; see [current implementation and limits](RPI_PING.md).

Further follow-up: recovery of the provisioned wired profile while unplugged is now implemented. Actual cable removal, backend reset, automatic AutoIP acquisition after reconnection, and restoration to the previous static profile were verified. See [current disconnected-reset implementation](RPI_DISCONNECTED_RESET.md). The old active-profile-only gap above is historical; full local credential reset and unplugged boot were not repeated in this network-only test.

Implement blank-field defaults and identification schema/error handling first, then complete mDNS disable and disconnected LCI. Prepare an isolated network fixture for lease/duplicate/name tests, and separately plan the IVI driver. A final review must map every applicable rule and its conditional scope; no percentage-complete score is asserted here.

HiSLIP, VXI-11, synchronization/trigger extensions, IPv6 and LXI Security are not automatically mandatory merely because they exist. Do not promote their entire API/certificate/security feature sets into core requirements. Identification-related requirements imported by Device 10.2 still apply. Declaring an extension would add its own requirements.

This audit changed documentation only. It did not change IPs, names, passwords, discovery state, radio settings or startup policy, and did not stop the running application/helper/panel.
