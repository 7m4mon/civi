# パーシャルリセット後の実測基準とreset実機試験 — 2026-11-08

ユーザーがIC-7300でパーシャルリセットを実行。その直後の状態を読み取り、
CIVIの`RAD:RESET`とPythonクライアントのreset基準を更新した。
仮定していた7.100 MHz/USB/FIL1は採用しない。

## 取得

最初はCI-V接続が隔離中だった。値を推測せず取得を停止し、ユーザーがUSBを
再接続してWebのRecover connectionを実行した後で取得を再開した。
識別応答はCIVI Project,CIVI/IC-7300,CIVI-0001,0.1.0。
`tools/capture_reset_state.py`で**305項目、エラー0**を読み取った。
開始/終了時の周波数・モード・PTT一致も確認した。取得処理は設定を送らない。

取得した主な値:

| 項目 | 実測値 |
|---|---|
| 両VFO周波数 | 14.100000 MHz |
| 両VFOモード | USB / DATA OFF / FIL2 (`010002`) |
| PTT、VOX、BK-IN、チューナー | OFF |
| Split、RIT、⊿TX | OFF、offset 0 Hz |
| PREAMP / AGC | PRE1 / MID |
| RFGAIN / AFGAIN / SQL | raw 255 / 1 / 65 |
| スコープ動作 / 転送 | OFF / OFF |
| スコープSPAN | 25 kHz |

VFOの問い合わせはSELECTED/OTHERで、絶対A/B選択の取得はできない。
両者の値が同じだったため、A/Bを推測せず両方を同一の実測値へ戻す基準にした。
この実機の取得時の状態であり、全地域/全ファームの工場既定値ではない。
AFGAIN/SQL等には本体ツマミ位置による値も含まれる。

## 反映範囲

`civi/profiles/ic7300-reset.json`に、両VFOと通常運用45項目＋スコープ12項目を保存。
完全な取得データはGit対象外に保管し、プロフィールには復元対象だけを収録した。
取得原本のSHA-256をプロフィールへ記録した。
メニュー216項目、校正、通信/USB、時計、メモリー、保存済みスコープバンドエッジ等を
自動書戻しの対象にしない。既存の書込権限を迂回しない。
したがって本体のパーシャルリセット全体を再現する命令ではない。

## 実機試験

1. 実測プロフィールの全復元項目が現在値と一致することを確認。
2. 受信中に選択VFOを14.101 MHzへ一時変更し、読取で変化を確認。
3. `RAD:RESET`実行後、両VFOと57項目の一致を確認。
4. PTT OFFと、日付/時計を除くメニュー214項目が取得時と一致することを確認。

初回は未開始CWへの停止命令17 FFがNAKとなり、resetは成功を返さなかった。
周波数は元の14.100 MHzへ戻した。その記録を残したうえで、CW/ボイス停止を
CIVIが所有する出力がある場合だけに限定した。所有中の停止NAKは引き続き失敗となる。

修正後は**7.006秒で成功**、PTT OFF、保護メニュー差分0。
さらに通常I/O既定5秒のクライアントでも、専用30秒待ちによって**7.016秒で成功**し、
通常タイムアウトが5秒へ戻ることを確認した。自動送信開始は一度も行っていない。
クライアント以外の本体/外部操作による送信を保証する機能ではない。

CIVI本体だけをPiの既存デスクトップ端末で再起動し、ヘルパー・パネルは維持した。
自動起動は追加せず、IP/資格情報も変更していない。
全自動試験は**293成功・1スキップ（27.56秒）**。
