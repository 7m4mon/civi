The statements below about the previous process awaiting restart describe the earlier fixture test.

Installed Debian authbind 2.2.0 on the Pi 4. `/etc/authbind/byport/443` is owned by `nom:nom`, mode 0500; verified bind to `0.0.0.0:443` as UID 1000. The low-port threshold remains 1024. No Python capabilities, global sysctl changes, proxy, service or automatic startup were added. See [setup and undo](RPI_HTTPS.md).

Started a separate mock-backend CIVI through the updated `bash start.sh`, as `nom`, using HTTPS 443 plus 18443, SCPI 15029 and temporary state/certificates. Discovery was initially disabled. The existing production application occupied 8443 and was left undisturbed. No serial port or production credentials were used by the fixture.

From the separate Windows PC, trusting the fixture certificate and retaining hostname verification:

- Fetched `/`, `/lxi`, `/network` and `/lxi/identification` over both 443 and 18443 through wired `192.168.73.2`, WLAN `192.168.4.54` and `civi.local`: 24 successful requests.
- An unauthenticated `/api/status` returned 401.
- Created an authenticated session and completed ten concurrent pairs of HTTPS `/api/scpi` and TCP SCPI `*IDN?` queries. Responses matched the simulated IC-7300 profile.
- Verified the application process ran as `nom`.

Separately registered a uniquely named temporary Avahi group using CIVI's Pi discovery code, without changing the global hostname. The Windows PC received `_lxi._tcp` and `_https._tcp` records targeting `civi.local.` port 443. The group was withdrawn afterwards.

Stopped the mock fixture and verified its 443/18443/15029 sockets were released; the pre-existing 5025/8443 listeners remained. Backed up the Pi's production configuration and changed its settings to 443 plus 8443 for the next manual launch. The current production process still uses its old listeners until restarted.

This verifies real port 443 and cross-machine TLS/authentication with a simulated backend. Production 443/8443 operation after restart, browser interaction, reboot persistence, full TLS/security requirements and LXI conformance are not established by this test. The production certificate includes `civi.local` but lacks numerical Pi addresses; it was not overwritten, and numerical-IP browser access may still show a certificate warning.
