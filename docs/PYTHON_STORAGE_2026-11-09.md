# Pythonクライアント0.5.0 保存データAPI — 2026-11-09

メモリー101チャンネル（1..99、P1/P2）、バンドスタック11バンド×3枠、
保存キーヤーM1..M8の型付きAPIを追加。選択・メモリーモード・現在値保存・
VFOコピー・選択中チャンネル消去も用意しました。
今回はWindows上の独立模擬環境と実ゲートウェイTCP＋MockBackendのみで検証。
Pi・実無線機を操作せず、IVI適合/登録済みとは表示しません。

## データと制約

`MemorySettings`は周波数、モード、フィルター、DATA、トーンモード、2つのトーン周波数を保持。
`MemoryRecord`は受信側/送信側の2ブロック、Split、選択グループ、10バイトの名前を保持。
Split OFFでも送信側を捨てず、半角カナと名前の末尾スペースも保存します。
空きチャンネルはNone。通常チャンネルはアドレス指定で消去でき、P1/P2へのその消去は拒否。
P1/P2書込はSplit OFF・選択グループ0を要求します。
[APIと使用例](../drivers/civi-ic7300/src/civi_ic7300/STORAGE.md)を配布物にも同梱。

レコード形式は30 kHz..74.8 MHzですが、現行プロファイルの書込範囲は30 kHz..60 MHzです。
キーヤーは最大70文字の保存APIで、CW送出は行いません。
保存データの書込は既存の`[permissions].memory`に従い、既定は不許可。
menu/link/calibrationとは独立。自動エラー照会OFFでも書込前後のエラーを確認します。
実ゲートウェイの権限をクライアントから有効化する機能はありません。

`write_and_read`は同じセッション内の割込みを防ぎますが、他クライアントや本体操作を
排除できません。選択中メモリーへの旧来操作は、その時点の無線機の選択に依存します。
バックアップ/編集にはチャンネル指定を使用してください。P1/P2の消去保護は
アドレス指定APIに対するもので、選択中メモリー消去の全動作を保証しません。

## 検証結果

- 保存API専用26成功、クライアント全体85成功。
- 全体 **370成功・Linux専用1スキップ（30.25秒）**。
- 両模擬系で101チャンネル、33枠、8キーヤーを読取→変更→読戻し→復元。
  空きP1/P2はアドレス指定で消せないため、使い捨て模擬環境で先に有効値を作り、
  その値を退避・復元する試験です。実機保存内容の復元確認ではありません。
- 独立したCI-Vバイト列で両ブロック、Split/select、トーン、名前、バンド/枠、
  キーヤー70バイトpaddingとFF消去を照合。
- 権限既定拒否とメニュー権限との分離、範囲外入力/応答、P1/P2制約、並行読戻し、
  NAK/シリアルtimeoutエラー/事前エラーで後続読戻しを行わないことを確認。
  timeoutはゲートウェイが返すシリアルエラーの注入で、物理USB試験ではありません。
- 受信resetで保存データ/権限が残ることを両模擬系で確認。
- mypy 2.4.1 strict: 9ソース、エラー0。
- sdistからwheelをビルド。別venvへオフライン導入し、Python isolated modeで
  レコード/バンドスタック/キーヤー、既定拒否と権限分離、同梱説明を確認。
  ゲートウェイのimport・第三者ランタイム依存はありません。
- 導入済みwheelの型情報で正しい利用例を受理し、意図的な誤代入3件をすべて検出。
