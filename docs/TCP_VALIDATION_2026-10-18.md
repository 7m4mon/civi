# IC-7300 TCP / VISA SOCKET 実機通し試験 — 2026-10-18

## 条件

- Windows / Python 3.14.5、CIVI 0.1.0、IC-7300、COM25、115200bps、無線機94h / コントローラーE0h。
- 製品の`civi.__main__.run()`で実サーバーを起動。`backend=civ`と既存TLS証明書を使用。
- 今回の試験用設定は`bind=127.0.0.1`、SCPI TCP5025、HTTPS8443、discovery OFF。永続config.tomlは変更せず、送信と永続設定等の書き込み権限も既定無効のまま。
- HTTPSは試験プロセス内だけの一時パスワードで認証し、既存証明書を信頼アンカーに指定してホスト名・証明書検証を有効化。認証情報は記録に含めない。
- PyVISA 1.16.2 / pyvisa-py 0.8.1、`ResourceManager('@py')`、`TCPIP0::127.0.0.1::5025::SOCKET`、read/write LF終端、timeout 5000ms。
- ソケットクライアントから実OSのTCP接続を行い、USBシリアル先の実機応答まで確認。モックや制御サービスへの直接呼出しで代用していない。

## NAKと試験スクリプトの修正

- `RAD:TXINHIBIT?`（16 66）は前回同様NAK。原因未特定であり、成功扱いにしない。
- `RAD:FILTER:SHAPE?`（16 56）は今回のAM状態でNAK。一時的にLSBへ変更すると取得できたため、少なくともこの実機ではモード条件によって応答が異なる。AMへ復元している。
- PyVISA ResourceManagerをコンテキストマネージャーとして使う試験コードが失敗したため、明示的なcloseへ変更した。CIVIの失敗ではない。
- 波形開始直後の-230エラーには引用文字列内のセミコロンが含まれる。試験コードの単純な末尾セミコロン分割を修正し、完全な掃引を待って取得した。これもCIVIのプロトコル不良ではない。
- TCP/HTTPS/PyVISAの成功結果を保持し、スコープとソケット再接続だけ別の起動セッションで再確認した。結果は複数セッションを合わせた記録である。

## 検証の限界

今回の通信は同じPC内のlocalhost経由。別のLAN端末、Windowsファイアウォール越し、NI-VISA、LabVIEW、VXI-11/HiSLIP、ブラウザ画面の手動操作、実送信、USB切断/電源断は今回の対象外。HTTPSはWebが使うAPI経由の実機試験であり、ブラウザ操作とは区別する。

Sメーターは変動するため、時点が異なるTCPとVISAの数値一致は求めていない。スコープは未校正raw値の475点取得を確認したもので、RFレベルの校正を示すものではない。

製品コードに変更はない。試験用コードと生ログはローカルのgit対象外`tmp/hardware_tcp_socket.py`、`tmp/hardware-tcp-report.json`、`tmp/hardware-tcp-wire.log`に保存。通常の自動テストへ実機操作は追加していない。
