# Pi LAN適用・保存・復元の実機試験

## 構成

- Raspberry Pi 4、Debian 13.7（aarch64）、Python 3.13.5、NetworkManager/nmcli 1.52.1。
- PCとPiは有線100 Mbpsで直結。PC 192.168.73.1/24、Piの基準値192.168.73.2/24。
- WLAN 192.168.4.54を管理経路として維持。既定ルートはWLANのまま。
- 手動起動のLAN補助プロセスと、通常ユーザーで動かす模擬無線機の試験サーバーを使用。実機USBや送信は使わない。
- 試験用HTTPS 18443。試験証明書にWLAN・有線の各IPを含め、CA信頼・ホスト名検証を有効にしたWindowsクライアントから操作。

## 成功した試験

1. 設定プレビューは適用を行わない。
2. Web APIから有線を192.168.73.2→192.168.73.3へ一時変更。
3. 変更後の有線IPから証明書検証付きHTTPSで到達し、現在値を取得。
4. WLANからの確定要求は409で拒否。
5. 新しい有線IPから確定して保存。
6. 192.168.73.2へ戻して有線から確定保存。
7. 再度.3へ一時変更し、確認せずに90秒の期限を待つ。NetworkManagerが.2へ復元し、保存項目と稼働中アドレスの一致を確認。
8. DHCP＋AutoIPを30秒の期限で一時適用。DHCPサーバーのない直結で169.254.108.9/16を取得し、期限後に.2へ戻ることを確認。
9. 最終的にPCから.2へのPingは2/2成功、損失0%。WLANの既定経路、Piの有線プロファイルと現在値も確認。

固定IPのHTTPS試験は10個のチェックがすべて成功しました。AutoIPはPi上のローカルUnixソケット経由で適用・観測した試験です。AutoIPへの別LAN端末からのHTTPS接続や確定は今回の対象外です。

## 検出・修正したNetplan連携の問題

初回は`connection modify --temporary`でプロファイルを変更した後に確定保存し、Netplan生成プロファイルがNetworkManager上で削除扱いになる問題を検出しました。確定要求は応答タイムアウトとなり、有線アドレスも消えました。成功として数えていません。

WLANから調査し、対象有線UUIDの実行時メタファイルだけをバックアップへ退避、対象プロファイルを再読込して基準値.2へ復旧しました。Wi-Fi設定やOS全体のネットワーク再起動は行っていません。

一時適用を`nmcli device modify`へ変更し、確定までは接続プロファイルを変更しない方式に修正しました。確定保存後にもUUIDと稼働中IPv4を再確認してからチェックポイントを解除します。修正後に上記の成功試験を実施しました。

## 限界と終了状態

DHCPサーバーからのリース取得、ゲートウェイ/DNSの変更、ホスト名、ケーブル断、NetworkManager自体の停止、電源断・再起動、IPv6は未試験です。復元は読み戻した項目の一致までで、すべてのネットワーク条件を保証するものではありません。

試験用WebサーバーとLAN補助プロセスを終了し、15025/18443/5025/8443に待受がないことを確認しました。自動起動・systemd・恒久的なsudo権限変更は追加していません。実験用コードと生の結果は追跡対象外tmpに保存しています。LXI全必須要件の適合を示すものではありません。
