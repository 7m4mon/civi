# Raspberry Pi 4 LAN SCPI実機確認（2026-10-19）

Windowsから、ユーザーが手動起動したRaspberry Pi 4のCIVIへLAN経由で接続しました。ラズパイにUSB接続されたIC-7300への実際の応答を確認しています。模擬バックエンドやlocalhostでの試験ではありません。自動起動の設定・サーバーの起動停止は行っていません。

## 接続と条件

- TCP 5025、LF終端。
- `*IDN?`: `CIVI Project,CIVI/IC-7300,CIVI-0001,0.1.0`。
- PyVISA `@py` の `TCPIP0::<PiのIP>::5025::SOCKET`。
- 開始時: 周波数774000 Hz、AM、VFOモードレコード`020002`、PTT OFF、VOX OFF、スコープON・転送OFF。
- ユーザー報告: USBシリアルは `/dev/serial/by-id/` のIC-7300デバイス、ユーザーはdialout所属。OS更新済み。OSの版・アーキテクチャ・Pi側Python版は今回未採取です。

## 結果

| 項目 | 結果 |
|---|---|
| 識別、周波数、モード、Sメーター、PTT取得 | 成功。Sメーター例raw 73、PyVISAでraw 71（時変値） |
| 周波数変更・読み戻し・復元 | 774000 → 775000 → 774000 Hz。エラーなし |
| 設定命令の無応答、LFパイプライン、`*OPC?` | 設定後の応答が`1`、`775000`、`0,"No error"`の3行で一致 |
| 拡張303定義の代表引数による取得 | 301成功、2件NAK（下記） |
| TCP 2接続の同時取得 | 各10回、計20組の周波数取得＋独立エラー取得で混線なし |
| 未知命令、エラーキュー分離、`*CLS` | `ERROR`と-113を発生元だけで取得、他接続はエラーなし。クリア成功 |
| TCP切断・再接続 | 識別取得成功 |
| スコープ | 転送を一時ONにして475点の波形JSONを取得、転送中の周波数取得も成功 |
| PyVISA RAW SOCKET | IDN、周波数、モード、Sメーター、PTT、OPC、エラー取得成功 |
| 復元 | 周波数774000 Hz、モードレコード`020002`、スコープON・転送OFF。最終PTT OFF |

NAKは次の2件です。Windows実機試験と同じ結果で、通信成功として数えていません。

- `RAD:TXINHIBIT?`: `-200,"Radio rejected CI-V 16 66 (NAK)"`。
- `RAD:FILTER:SHAPE?`: AMで `-200,"Radio rejected CI-V 16 56 (NAK)"`。今回モード変更は行っていません。以前のWindows試験ではLSBで取得できています。

## 範囲と制限

手動試験を基本操作と追加メニュー/スコープ/PyVISAの2段階で実施しました。303件は定義ごとの代表セレクターによる読み取りであり、全値・全チャンネルの試験ではありません。変更試験は周波数とスコープ転送のみです。送信、校正・メニュー書込み、ネットワーク設定変更、systemd設定は行っていません。サーバーは起動したままです。

ユーザーによるWebスコープ表示成功の報告はありますが、今回のエージェント試験はSCPI TCPに限定しています。HTTPSとの同時操作、NI-VISA、長時間運用、USB切断・再接続、電源再投入時の復旧は今回未確認です。

生の応答と試験ハーネスはローカルの追跡対象外`tmp/rpi-scpi-report.json`、`tmp/rpi_scpi_check.py`、`tmp/rpi_scpi_extra.py`に保存しています。
