# CIVI receive reset / IVI reset

2026-11-08。IC-7300の公式補足説明書（A7290-2J-8、印刷3–8ページ）の
CI-Vコマンド一覧には、パーシャルリセット/オールリセットの命令はない。
18 00/01は電源OFF/ONで、リセットの代わりにはならない。
[公式配布ページ](https://www.icom.co.jp/support/manual/2557/)。

[IVI Core 1.0のReset](https://github.com/IviFoundation/IviDrivers/blob/main/IviDriverCore/1.0/Spec/IviDriverCore.md#reset)
は機器を既知の状態に置く動作を要求し、必ずしも工場初期化命令とは限らない。
以下はCIVIが定義する受信基準状態への復帰であり、**IcomのPartial Resetではない**。
IVI適合の最終判断は、この動作だけでは行わない。

## 操作

更新済みCIVIにSCPIで `RAD:RESET;SYST:ERR?` を送る。
成功は `0,"No error"`。`RAD:RESET`単体は通常応答なし。
`RADio:RESET`も受理する。引数と`RAD:RESET?`は提供しない。
`*RST`は従来どおり未提供。`*OPC?`は後続させられるが、エラーキューも
確認すること。1だけでは先行設定の成功を判定できない。
以前のエラーが残っている場合もキューから返るため、先に内容を確認する。

Pythonクライアント0.2.0は `device.ivi_utility.reset()` または
コンストラクターの `reset=True` で同じ操作を使う。
**実行すると無線機の運用設定が変わり、自動的な元設定への復元はしない。**
Python側は事前に既存エラーを読み、あれば例外として変更前に中止する。
リセット後のエラーも、操作後状態照会のON/OFFに関係なく確認する。
旧CIVIがこの命令を知らない場合はUndefined headerの例外になる。
模擬動作ではネットワークに接続せず、模擬周波数とモードを戻す。

## 受信基準状態

1. PTT OFFを要求し、CIVIが開始したCI-V CW出力・ボイス再生があれば停止。
2. VOX、BK-IN、チューナーをOFFにし、PTTがOFFであることを読む。
3. スキャン停止、VFOモード、VFO A選択。
4. 両VFOを実測した14.100000 MHz、USB、DATA OFF、FIL2へ設定。
5. `civi/profiles/ic7300-reset.json`に記録した通常運用・スコープ57項目を復元。
   Split/RIT/⊿TX OFF、offset 0、PRE1、AGC MID、RFGAIN 255、AFGAIN 1等。
6. VOX/BK-IN/チューナー/両VFOと57項目を読み返す。
   表示周波数・表示モード・PTT状態も確認し、すべて一致した場合だけ完了記録を残す。

ユーザーが2026-11-08にパーシャルリセットした実機から305項目を読み取り、
その時点の状態を基準にした。これは全機種/全地域に共通の工場既定値の主張ではない。
両VFOの読取値は一致していたため、A/Bの取得時選択を推測せず同じ値へ戻せる。
音量/RFゲインもこの個体の取得値を復元する。本体ツマミを動かすと変化する。
スコープはENABLE/STREAM OFF、SPAN 25 kHz等、取得した通常設定を復元する。
メモリーチャンネル、メニュー216項目、校正/調整値、保存済みスコープバンドエッジ、
CI-V接続設定、CIVI設定、IP/ホスト名/Webパスワードは対象外。
メニュー書込権限を迂回せず、時計や調整値も書き戻さない。

## 完了と障害

共有制御キュー内の1操作として実行し、途中のWeb/SCPI操作を割り込ませない。
各CI-V設定のACKと読取結果を確認し、NAK・通信障害・不一致でその時点で停止する。
途中まで適用された設定を自動でロールバックしない。状態を再確認してから再実行する。
隔離されたCI-V接続は解除せず、既存のRecover connection手順が必要。
対象はIC-7300プロファイルと確認済み機種IDが一致した接続に限定する。

送信開始命令は送らず、送信制御が無効でも停止操作は利用できる。
外部PTT/キー等による送信やUSB断中の停止は保証しない。実行中にPTTがONのまま、
または最後にONになった場合は失敗とする。別クライアントや本体の操作が
完了後に設定を変更することまでは禁止しない。

## 検証範囲

模擬バックエンドで両VFOと実測基準状態、メモリー/設定の保持、送信制御を有効化せずに
停止できること、NAK時の打ち切り、読取不一致、通信断、同時操作の非混線を検証。
Pythonクライアントでも模擬SCPI接続によるresetと事前エラー時の中止を検証。
実機で14.101 MHzへ一時変更後、resetで14.100 MHzと両VFO・57項目を復元。
約7秒で完了し、PTT OFF、時計以外のメニュー214項目が取得時と一致した。
初回に未開始CWへの17 FFがNAKとなったため、CW/ボイス停止を所有中のみへ修正。
所有中の停止NAKを無視しないことも回帰試験に含めた。
クライアントのreset専用待ち時間は既定30秒（`reset(timeout_ms=...)`で指定可能）。
終了後は通常I/Oの待ち時間へ戻し、通常既定5秒のクライアントでも実機完了を確認。
全体293成功・1スキップ。[取得・実機記録](PARTIAL_RESET_CAPTURE_2026-11-08.md)。
