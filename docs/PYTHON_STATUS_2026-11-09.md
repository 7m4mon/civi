# Pythonクライアント0.10.0 状態照会 — 2026-11-09

[Coreの状態照会規定](https://github.com/IviFoundation/IviDrivers/blob/main/IviDriverCore/1.0/Spec/IviDriverCore.md#query-instrument-status-enabled)
に対する一次監査の指摘を修正しました。全ての型付きAPIで状態照会設定に従い、
OFF時には自動のSYST:ERR?を送信しません。既定値は従来どおりOFFです。
初期化、保護書込、スコープ開始/停止、resetも対象です。

## 挙動と移行

- `with device.checked():`でセッションをロックし、その範囲を一時的にONにする。
  入れ子・例外があっても元の設定へ復帰し、他スレッドへ一時設定を漏らさない。
- ONでは型付き操作後のエラーを確認。保護書込では事前確認も維持する。
  STOP/OFFは事前エラーがあっても停止を試み、事前/新規のエラーを報告する。
- OFFでは設定処理完了を待っても、権限拒否/NAK/シリアル失敗がキューに残る場合がある。
  `write_and_read`が元の値を返しても、書込成功の証明にはならない。
  検証が必要な変更/読戻し/復元はchecked()または明示的なONで行う。
- ERRORを返した生queryとOFFの型付きqueryは`QueryError`を送出し、キューを消費しない。
  エラー詳細は明示的なerror_query等で取得する。ONの型付きqueryはDeviceErrorで詳細を返す。
- 生query/Direct I/Oはchecked()内でも自動状態照会を行わない。
  明示的なエラー照会は設定に関係なく利用可能。
- resetはRAD:RESET;*OPC?で処理完了を待ち、キュー確認は設定に従う。
  ONなら事前/結果を確認し、OFFなら失敗はキューに残す。タイムアウトの復元は維持。

[APIと移行例](../drivers/civi-ic7300/src/civi_ic7300/STATUS.md)を配布物へ同梱。
既存の失敗検出を必要とする利用者は、ONまたはchecked()を明示してください。
ゲートウェイの実権限、送信所有権・最大時間・切断時停止は変更していません。

## 検証結果

- 新規11成功、クライアント/配布関連165成功。
- 全体 **450成功・Linux専用1スキップ（32.27秒）**。
- 模擬TCPと独立シミュレーターで、保護API各群のOFF時にエラー照会が送られないことを
  実送信プログラムから確認。権限拒否等がキューに残ることも確認。
- 初期化のID照会/状態照会ON/OFFの4組合せ、query失敗時のキュー保持、
  checked()の例外/入れ子/スレッド間の設定復帰を検証。
- 既存の権限/NAK/timeout/停止失敗等の試験は、ON/checked()を明示して継続。
  旧仕様の隠れた状態照会に依存しないよう更新。
- strict型検査12ソース、エラー0。sdist/wheel整合検査、別venvへのオフライン導入、
  isolated modeで状態照会・reset・エラー保持・同梱説明を確認。
- 導入済み型情報でchecked()の戻り値を型付きドライバーとして扱え、誤代入を検出。

Pi・無線機を操作せず、実機ゲートウェイも変更していません。
状態照会の指摘はこの範囲で修正しましたが、命名・繰返し機能の階層・文書・実機/環境検証と
登録は残るため、IVI適合・登録済みとは表示しません。
