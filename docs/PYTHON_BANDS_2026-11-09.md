バンド端5定義、DATA/フィルター設定とIP+別コマンドを追加。

## APIと制約

`device.bands`から既定バンド端、工場/ユーザー定義数、番号指定のバンド端読取と
ユーザー定義の書込/読戻しを提供。`BandEdges`は下限/上限のHzと2D区切りを持つ
11バイト形式を検証し、数値範囲0..74.8 MHz、下限<=上限とします。
実機の国/地域別バンドプランや送信可能性を推測する機能ではありません。
ユーザー書込は既存のcalibration権限（既定OFF）に従い、自動状態照会OFFでも前後のエラーを確認。
模擬のcalibration権限はメニューと共有し、menu/link/memoryとは独立しています。
実ゲートウェイの権限をクライアントから変える機能はありません。

`radio.data_filter: DataFilter`はDATA ONでFIL1..3、OFF読取で0..3、OFF書込で0のみを許可。
OFF読値に残ったフィルター番号を黙って捨てて書き戻さず、I/O前に拒否します。
特定フィルターを保って戻す際は、完全な`VfoMode`を退避・復元します。
`radio.ip_plus_alternate_enabled`は既存IP+と同じ状態の別CI-Vコマンドです。
これらスカラーのエラー確認は既存の`query_instrument_status`オプションに従います。
[配布物のAPI詳細](../drivers/civi-ic7300/src/civi_ic7300/BANDS.md)に例と制約を記載。

## 検証

- 新規25成功、クライアント全体126成功。
- 全体 **411成功・Linux専用1スキップ（30.70秒）**。
- 両模擬系で番号1..30のバンド端を読取→変更→読戻し→元値復元。
  模擬データの件数は0、番号指定には定型レコードを返すため、実機に30バンドある証明ではありません。
  実機では最新の件数と機種資料を確認して有効な番号を使用する必要があります。
- データ上の下限0/上限74.8 MHz、BCD/2D区切り、番号BCDの独立した送信バイト列、
  calibration既定拒否、権限共有/分離、reset後の保存データ保持を確認。
- DATA ON/FIL1..3とOFFの書込/実値読戻し、VFOモードを使った復元、IP+両コマンド間の
  状態共有を確認。独立模擬ではDATAをVFO/メモリー作業状態へ反映。
  ゲートウェイMockBackendのDATAはVFOモードと独立した保存値で、実機の副作用を再現しません。
- 不正な型/番号/BCD/範囲/応答、NAK/シリアルtimeoutエラー注入/事前エラーでの
  後続読戻し抑止、同一セッションの並行書込/読戻しを確認。
- mypy strict: 11ソース、エラー0。
- sdist/wheel作成、別venvへオフライン導入。isolated modeで保存データ/権限/DATA/IP+と
  同梱説明、ゲートウェイ非依存を確認。導入済み型情報で正常例を受理し、誤用3件を検出。

模擬データは国/地域別の工場設定や電波法上の送信範囲を表しません。
実機の保存永続性、バンド定義数の変化、モードごとのDATA制限とRF動作は未確認です。
残る11定義と仕様全体の照合、命名/文書/登録は引き続き必要で、IVI適合/登録は未達です。
